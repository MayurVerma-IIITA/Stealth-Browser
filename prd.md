Technical Architecture Analysis1. Preventing Cross-App DetectionIn a standard desktop environment, software suites detect other running applications through specific application programming interfaces (APIs) provided by the operating system. Understanding these entry points is key to designing an overlay that remains undetected:Window Enumeration Hooks: Monitoring software often scans active desktop elements using native functions like EnumWindows or GetForegroundWindow to identify which program currently has user focus.Focus State Detection: Web-based trackers and native security shells check for blur events or focus switching. If a user clicks into a standard secondary application window, the primary window loses its active state, triggering a notification or warning.The Desktop Window Manager (DWM) Solution: To bypass focus-loss alerts entirely, the overlay application must be configured as a non-interactive, transparent graphical layer. By applying the extended window style WS_EX_NOACTIVATE along with WS_EX_TRANSPARENT, the window can be drawn directly on screen without ever requesting input focus from the operating system. This ensures that the primary underlying software remains the active application in the eyes of any background tracking loops.2. Local Control Interface via Keyboard ShortcutsBecause the application window will completely lack structural frames, toolbars, or visible title bars, management must rely entirely on low-level keyboard interaction hooks.Global Hotkey Hooks: Standard application shortcuts only fire when the application is actively selected by the user. Since this utility is built to avoid taking active focus, it must register global hooks via the Windows API function RegisterHotKey.Execution Behavior: This forces the operating system to listen for specific multi-key combinations (such as Ctrl + Alt + Shift + O) at a system-wide level. When pressed, the hook intercepts the command and changes the application's rendering state (e.g., toggling its visibility or adjusting opacity) instantly, without requiring an active mouse click.3. Ephemeral In-Memory Data StorageTo ensure no digital footprint remains on the local disk, traditional persistent databases or browser cache files should be avoided.In-Memory Virtual File Systems: The optimal approach for a stealth web utility is to utilize volatile RAM storage. Modern browser components (such as Chromium-based web engines) can be forced into an "Off-The-Record" profile.Data Lifecycle: This profile structures all browser history, session states, active tracking cookies, and temporary site files within volatile system memory (RAM). The moment the application process is terminated via hotkey or task termination, the allocated RAM blocks are cleared, ensuring that no permanent cache footprint is written to the physical storage drive.Product Requirements Document (PRD)1. Introduction & ObjectivesThis document establishes the functional requirements for a lightweight, cross-platform overlay utility designed for Windows environments. The application serves as an isolated, floating browser layer capable of displaying web documents transparently without modifying the foreground focus or active state of concurrent desktop applications.2. Functional RequirementsArchitectural Interface & RenderingOverlay Status: The window must render on top of all existing desktop applications using the WS_EX_TOPMOST extended attribute.Window Styling: The system must strip all window decorations, including drop shadows, minimize/maximize buttons, borders, and taskbar icons using WS_EX_TOOLWINDOW.Opacity Adjustments: The application layer must accept real-time alpha channel adjustments ranging from 0.05 (near-total transparency) to 1.0 (fully opaque).Focus Preservation (Anti-Detection)Focus Bypass: The application must utilize the WS_EX_NOACTIVATE window configuration to prevent its interface from registering as an active foreground window when clicked or interacted with.Input Forwarding: When click-through mode is enabled via hotkey, the application must apply WS_EX_TRANSPARENT, passing all mouse clicks directly down to whatever software is currently positioned underneath the overlay.Control InterfaceSystem-Wide Key Registration: The application must bind to low-level keyboard listeners using native OS hooks to handle configuration commands globally.Hotkey Assignments:Ctrl + Shift + UP/DOWN: Increments or decrements window opacity levels by 10%.Ctrl + Shift + H: Toggles between fully visible and completely hidden rendering states.Ctrl + Shift + T: Toggles between interactive input mode and absolute click-through mode.Storage & Privacy EngineVolatile Isolation: The browser sub-component must initialize an isolated, non-persistent browsing profile.Disk Write Restriction: Persistent storage mechanisms for cookies, cache data, local storage variables, and navigation history must be redirected entirely to RAM or completely disabled.3. Non-Functional RequirementsResource Footprint: Memory allocation during standard browsing sessions must remain stable under a specified threshold (e.g., <150MB total RAM utilization) to prevent triggering automated system performance warnings.Portability: The application must compile into a single standalone binary capable of running instantly from memory or an external drive without executing a formal installation sequence or creating system registry keys.
